## MODIFIED Requirements

### Requirement: CI builds and attaches signed release APK on tags
The project SHALL build a signed release APK and attach it to the matching GitHub Release whenever a release is published. The build SHALL be triggered reliably by the release automation itself — as a job within the same workflow run that creates the release — because GitHub does not start new workflow runs from events generated by `GITHUB_TOKEN`. The existing `workflow_dispatch` trigger SHALL remain available for manual rebuilds.

#### Scenario: Release PR is merged
- **WHEN** release-please merges a Release PR and creates the tag and GitHub Release
- **THEN** the release APK build runs in the same workflow run and uploads `karoo-radar-<version>-release.apk` to the GitHub Release, with no manual step

#### Scenario: Manual rebuild for an existing tag
- **WHEN** a maintainer runs the build workflow manually with a tag
- **THEN** a signed release APK is built and attached to that release

#### Scenario: No dependency on GITHUB_TOKEN-generated events
- **WHEN** the release is created by release-please using the default `GITHUB_TOKEN`
- **THEN** the APK build still runs (it is not relying on the `release` or tag `push` event, which `GITHUB_TOKEN` cannot raise)
